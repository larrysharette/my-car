My Car is an application for keeping track of the maintenance, wishlist, and gas mileage. This is a very simple application. The following screens/features are as follows:
- SignIn Screen: Basic screen with username and password. One thing to note is that we don't have "users" we have "cars" in the database so the data is stored there
- Dashboard/Home Screen: There is a huge banner with the make, model, and year of the car with a background picture of that the user uploaded of the car. There should be some basic metrics about the car, stuff like average gas spend, average gas price, average miles driven, etc. Then we'll have quick actions like a button for recording a gas fill up, upload images/files, add wishlist item, etc. Maybe we have 2 sections/tables with 5 recently added maintenance logs, and wishlist items. We should have a reminders list of upcoming maintenance, which we get from `maintenanceLog` in  based on the mileage and/or the `plannedFor` and the `completedAt` is null. We should have some graphs too
- Log Gas Fillup Form: Refer to `gasLog` in  for the type of data we want to record in the form. The form experience is focused on quick and easy entry, we don't want too many required fields but what the db requires. An important thing that I would love to add is recording the GPS coordinates when the gas log is submitted so we'll need to ask GPS permissions. If the user records the car's odometer then we should update the cars' odometer, so we can use this information for maintenance reminders
- Maintenance Log Screen: This is a list of recent maintenance that has been performed on the car. We'll have search and filters (is planned, is completed, system, service type, date range of completed at). We'll have table and grid view. Grid card will have a banner image top is a random image from the `maintenanceFiles` where `fileType` is a image type. In case of no image, then have a gradient with the system/service. When clicked we go to the maintenance info screen. There should a create maintenance log form in dialog
- Create Maintenance Log Form: This is a very simple form that lets the user create a basic maintenance log and indicate whether it's a planned or one they're currently working on/just completed. The dialog actions are "Cancel", "Create", "Create and Edit". Create and Edit, creates the log and then navigates to the mainenance info screen
- Maintenance Info Screen: This is basic screen that shows all the information. Everything should be editable with an auto save feature. We should have parts table and file list section. The actions we need for this screen are: "Add Part", "Add File", "Add Image/Video". Add Image and Record Image both put their data in the same `maintenanceFiles` table but we use the camera ui to set it up or let the user choose from their gallery. We should have a image/video gallery on this screen
- Gas Log Screen: This is a simple screen with a table of the recorded gas log, each row has a view button that opens a dialog with all the gas log info with a map with the gps if it was recorded, we should be able to edit pieces of information in case we accidentally hit record before we were done. There should be some graphs showing gas price trends, miles per gallon trends, and whatever info we can pull from the gas log data. We should also have the Record Gas Log Form Dialog here as well.
- Car Files/Gallery Screen: This a gallery screen with a grid view that shows image previews in the cards. We should have screen and filters for file type and such. We'll also want the same "Add File" and "Add Image/Video" as the maintenance log screen. A difference here is that the table structure is different, and we have the ability to mark specific images as "Primary" which is what we'll use for the Dashboard/Home banner. We can also add "Descriptions" so we can have captions for searchability in case for instance we are recording a video to show a mechanic later for diagnosis.

For technical structure, I want to use server actions as much as possible because the application overall is very simple. When we deploy the application we'll be using Vercel's Database and Blog Storage, but when developing locally I want to use a local postgres db and local files/folder so we'll need utility wrappers for that functionality so that we can make the actions environment agnostic. 

Please use ShadCN for the component library, if we are missing any components then use the ShadCN cli to add those components. We should use tanstack table for the tables for handling pagination and such. For data retreival we should be grabbing the data server-side then passing them into the client components where necessary. I'd like to avoid tRPC or api calls if we can.
